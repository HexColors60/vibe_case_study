範例：Claude Code

以下是截至 2026 年 1 月，Claude Code 的情境設定功能概覽，以及它們在上述維度中的定位：

CLAUDE.md

類型：指引

誰使用：Claude Code（每個 session 一開始必定載入）

適用時機：整個專案中最常反覆出現的一般性慣例

範例：
-「我們使用 yarn，不使用 npm」
-「執行任何指令前，別忘了啟用虛擬環境」
-「重構時不考慮向後相容性」

備註：幾乎所有程式設計輔助工具都有這種主規則檔，並正嘗試標準化為 AGENTS.md

Rules

類型：指引

何時載入：當設定路徑下的檔案被載入時

用途：模組化指引、降低 CLAUDE.md 的常駐大小；可依檔案類型（如 *.ts）限定載入時機

範例：
-「撰寫 bash script 時，變數應使用 ${var} 而非 $var」（路徑：**/*.sh）

備註：越來越多工具支援這種基於路徑的規則（如 GitHub Copilot、Cursor）

Slash commands

類型：指令

誰觸發：人類

用途：你想手動觸發的常見任務（review、commit、test…）

狀態：Claude Code 中已棄用，改由 Skills 取代

Skills

類型：指引、指令、文件、腳本等

誰觸發：LLM 或人類

用途：僅在需要時才「延遲載入」的情境；可包含額外資源與腳本

範例：

JIRA 存取方式

React 元件撰寫慣例

XYZ API 整合說明

備註：Cursor 也正轉向類似 Claude Code 的 Skills 設計

Subagents

類型：指令＋模型與工具設定（獨立情境視窗，可平行）

用途：

適合獨立執行的大型任務

想用不同模型完成的任務

僅在特定任務中才需要的工具或 MCP server

可編排的工作流程

範例：

為剛完成的功能建立完整 E2E 測試

用不同模型做第二次 code review

備註：對 swarm 類實驗（如 claude-flow、Gas Town）是基礎功能

MCP Servers

類型：程式（透過 Model Context Protocol）

誰觸發：LLM

用途：讓代理能呼叫 API 或操作你機器上的工具

範例：

JIRA API 存取

瀏覽器操作（如 Playwright MCP）

本機知識庫存取

備註：目前主流程式設計輔助工具都已支援

Hooks

類型：腳本

觸發時機：Claude Code 生命週期事件

用途：在特定事件點「每次都確定發生」的行為

範例：

自訂通知

每次編輯 JS 檔後自動跑 prettier

記錄所有執行過的指令

備註：仍屬少見功能，Cursor 近期才開始支援

Plugins

類型：分發機制

用途：在組織內分享共用的指令、skills、hooks 設定

這看起來很多功能，但目前正處於「風暴期（storming）」；未來勢必會收斂成較簡單的一組功能。我預期 Skills 可能不只會吸收 slash commands，甚至也會整合 rules，讓整個表格少掉兩列。

Getting AI to Work in Complex Codebases
It seems pretty well-accepted that AI coding tools struggle with real production codebases. The Stanford study on AI's impact on developer productivity found:

A lot of the "extra code" shipped by AI tools ends up just reworking the slop that was shipped last week.
Coding agents are great for new projects or small changes, but in large established codebases, they can often make developers less productive.

演讲：为 Coding Agent 构建智能上下文：Qoder 的 Context Engineering 实践
ChatBot 时代“ Prompt 决定效果”；24 年底 Agent 形态爆发，单任务动辄几十上百次工具调用，动态上下文体量指数级膨胀，传统逐轮裁剪导致 Prompt Cache 失效、成本激增。Qoder 将上下文拆为静态 Prompt 与动态 Action/Observation，融合代码库分析、开发者行为感知、执行反馈、和网络实时信息获取四大维度，按“保留完整历史 + 工具输出精细裁剪 + Todo 持续引导”策略组装，配合 Prompt Cache 与错误回溯保留，实现 90% 延迟下降、5-20% 成本压缩，任务完成度和效果大幅度提升。本次演讲我将分享 Qoder 的 Context Engineering 实践。

演讲提纲

1. 静态上下文（Static Context）

System + User + Tools Prompt
2. 动态上下文（Dynamic Context）

基于代码库的上下文（Context From Codebase）
基于开发者行为的上下文（Context From Behavior）
基于执行反馈的上下文（Context From Execution）
基于互联网内容的上下文（Context From Internet）
3. 上下文组装的策略与实践

前缀保持稳定，最大化 Prompt Cache
多粒度语义蒸馏与重组
认知焦点持续性牵引
超限场景下的弹性降载
先验错误 & 过程错误的注入
